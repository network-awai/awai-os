# Circle Goal controller — AWAI-2864

This Otehon controller preserves each pinned source job's cron or interval and disabled/paused flags. Missing cron zones use the owner's Asia/Tokyo decision; interval phase starts at the explicit new-state epoch. Unsupported schedules and unavailable verified profiles are held. The118 unassigned Bots remain unassigned. Linear Cycle fields are never changed.

The owner authorized the Circle Goal rollout. Only public mission/role context and saved peer proposals enter Meta/MuseSpark1.3, low effort, one model step, no tools. Original script, email, payment and connector jobs remain separate and held. At most4 calls per Circle per JST day are admitted atomically with the canonical occurrence; uncertain claims consume budget and are never automatically replayed. Setup seeds have distinct job IDs, use the same budget and do not qualify source-cron execution.

The host controller registers a narrowly pinned enrollment using the separate administrator identity. The actual Muse process receives no ledger, Linear, storage credentials or tools. Worker identities can read enrollments and transact scoped occurrence/cursor records; they cannot edit enrollments. The three-node ledger runs on levi/benjamin/joseph. The initial inference executor is jun-control, not a qualified multi-host inference fleet or VM deployment. There is no VKE dependency or silent Native fallback.

Each invocation is bound before inference to a live, active Issue in the Bot's owning Project and original Initiative, Goal alignment, profile revision, source schedule, model and dated forecast. Intent, output and receipt are private durable application state. Saved output is independently read back from encrypted Kotobase/AwaiFS before completing the occurrence. Restart recovers that saved output without a second model call; an unresolved effect stays held. Linear writes use intent/readback and freeze ambiguous writes. Missing provider counters stay unknown; reasoning is an output subset and raw cache counters are not added without normalization evidence. Coding overhead is unallocated.

Public projections contain only minimal activity, evidence CIDs, Issue links, usage and proposal counts. They contain no prompt, full transcript, owner or private session identity. Animations require a fresh catalog-bound actual process heartbeat. Saved proposals are not verified business Goal outcomes. A new real ~/.itonami was owner-authorized; legacy conversations and old unknown effects have not been recovered. Original ledger/service roots remain untouched. New private database cold boot, off-host replication and host-loss recovery require separate qualification.

Operator preparation: `node prepare.mjs SOURCE_ROOT CATALOG SCHEDULES BASE_CONFIG`. It refuses an existing controller. Start `node worker.mjs CONFIG SHA256 seed|tick|serve` only after pin, ledger, source, storage and owning-Issue checks. The manifest pins the code and executables. `serve` wakes each minute but admits only the Bot's own due source slots; it does not create a shared Bot cadence. Missed unstarted work older than1 minute is skipped; no unknown work is replayed.

Checks: `node --test nixos/otehon/circle-work/test.mjs` uses synthetic model replies and real Kotobase/AwaiFS. Physical ledger contention tests use synthetic job IDs with zero inference calls. Do not count fixture admissions as live Bot work or usage.
