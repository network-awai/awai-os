# PostgreSQL prepared-root recovery — hosted experiment

The opt-in PostgreSQL witness now records a candidate root in a `pending bytea` column, guarded by the exact old root, before the local A/B root is published. The writer requires readback of that intent; after publication it verifies the complete Pack catalog and manifests, then atomically moves the pending root to the committed witness root and clears `pending`. A normal witnessed read refuses any pending intent. Old two-callback witnesses remain supported and do not acquire this guarantee.

`pack/reconcile-witnessed!` is an explicit operation under the local writer lock. It reads the trusted database root and pending intent and verifies all referenced Packs and manifests. If the selected local root equals the exact pending root, it CAS-commits the pending root and verifies readback. A repeated call with matching committed roots is idempotent. If local root is the old root while an intent remains, it refuses and preserves the intent: an old root may mean publication never happened, or that a newer published root was rolled back. A missing Pack, invalid root, changed witness or unrelated local root is refused; missing data does not advance the witness. This does not automatically authorize or implement pending cancellation.

Local macOS arm64 tests used Babashka 1.12.218 and an isolated PostgreSQL 14.19 Unix-socket cluster. Five actual four-Pack writer-kill boundaries were checked before and after a clean DB restart. After intent but before root publication, reads and reconciliation refused pending review; after root publication, verified reconciliation completed and then repeated idempotently. A separate forced DB interruption during the pre-commit CAS caused PostgreSQL WAL recovery; the saved intent matched the published local root. With one Pack temporarily withheld, reconciliation refused and the witness did not change; after the Pack was restored, reconciliation committed and the four-Pack group reopened. Test artifacts and the withheld-and-restored fixture are retained; the isolated server was stopped.

The database table must be explicitly provisioned with `store_id text PRIMARY KEY`, `root bytea NOT NULL`, and nullable `pending bytea`. Existing deployments with the earlier two-column experiment require an explicit, reviewed migration before using this version; no migration or production service is performed by this proof. The prior dated PostgreSQL witness note describes the earlier protocol and its claims of no reconciliation are historical. `check.nix` includes the hosted test; verify exact-head CI separately.

Trust remains external: the database and its service configuration must be authenticated, separately administered, and protected against rollback or privileged rewriting of pending/committed values. The local writer lock is not distributed fencing; existing unguarded APIs and callers must not be treated as protected. This local test is not independent-node, Native, OS-cache-loss or hardware-power-loss qualification. A service failure during reconciliation can leave the outcome uncertain and requires another status check; it is never reported as success without readback.
