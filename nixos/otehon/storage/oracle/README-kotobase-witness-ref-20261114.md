# Witnessed Kotobase ref and block backend — hosted experiment

`open-witnessed-backend` composes the witnessed block port with a prepared-witness `IRefStore`. It requires a trusted host-supplied bounded closure verifier. Every ref name and canonical CID, referenced block, and caller-approved closure is checked together with all supported Pack/IPLD catalog entries before a witnessed operation and before committing the candidate root. A stale ref CAS returns a negative receipt; missing targets and refused closures cannot publish. Interrupted publication retains the prepared intent; explicit `reconcile-witnessed-backend!` verifies all supported catalog entries and every ref closure before committing a matching pending root. Old-root/pending-new ambiguity still requires review. Existing unwitnessed APIs remain available but are not qualified by this port.

A local macOS arm64 test used the actual digest-pinned Forest tool and a task-owned PostgreSQL 14.19 Unix-socket cluster. It published a raw leaf, published/read its ref, refused a missing target and a denied closure, interrupted a ref update before witness CAS, and refused the pending ref read. With the Forest archive withheld, reconciliation refused and did not advance the witness; after restoration, reconciliation succeeded and was idempotent. A later block write with an existing ref also succeeded. The test's closure verifier is complete for **one known raw leaf only**; this is not evidence for a Prolly DAG closure, signed frontier, real policy or receipt. Separate unit tests check post-publication verifier refusal and that all of two refs are visited. Full hosted suite: 73 tests / 444 assertions. The full optional real-tool PostgreSQL script passed locally; Linux exact-head CI must be checked independently.

The PostgreSQL service and filesystem were on the same host. Authenticating the service, protecting database history and writer credentials from rollback or privileged modification, enforcing the supplied verifier's completeness and bounds, and routing every writer through this protocol remain host responsibilities. The local writer lock is not distributed fencing. This is not Native, OS-cache-loss, physical power-loss, independent-node or production qualification. The earlier dated block-port note states that no witnessed ref/backend existed at its date; this document records the subsequent implementation without rewriting that historical evidence.
