# Hosted GiB Prolly query reboot experiment — 2026-11-15

`atomic_gib_prolly_query.clj` records the actual logical-file CID of the prior guest-created 1 GiB synthetic file as a Prolly datom. The hosted atomic Forest stream stages the index, manifest and 1,024 file blocks and publishes its physical root/ref together. Before publication the callback opens the staged Prolly snapshot, runs a Datalog query for the file CID, resolves the resulting manifest and verifies every chunk and the full SHA-256 `1f7e0c0d3fefe5579e556a04f7796b7de01278916e49a6d31df864e16adf1708`.

After stopping and starting the dedicated Ubuntu Lima guest, a fresh process repeated that query and full verification with `GIB_SOURCE` and `FOREST_TOOL` pointing to nonexistent paths. The source store and writer therefore were not needed for readback. The guest boot ID changed and all 80 recorded store, source-code and probe files matched their pre-reboot hashes. `/usr/bin/time -v` measured one write at 49.99 s / 517,152 KiB maximum RSS and one read at 18.70 s / 477,636 KiB. The file is mostly-zero synthetic data, guest OS cache was lost but host cache was uncontrolled, so these are not storage performance or power-loss results.

This probe does not bind its index to the separately demonstrated signed basis, policy, governed query or receipt. It uses identity transforms and fixture blind/digest functions, no real capability check, independent witness, Native I/O, live AwaiVol or remote durability. A production connection must bind and verify these together; the local group/ref is not a distributed transaction. The previous signed-receipt experiment uses a different Prolly basis and does not establish this binding.

Task-local evidence `.agent-output/gib-prolly-reboot-evidence.tar.gz` SHA-256 `f2fb4ae8bd809fbb0814b051379decd6d2d37635d67958b885e3aacc0e6ee09a` contains guest probe, timings, outputs, boot IDs and checksums. Guest store and staging remain preserved. Source and dependencies are the same pinned hosted environment used by the adjacent unified receipt experiment; no JVM oracle is introduced into Native or CI.
