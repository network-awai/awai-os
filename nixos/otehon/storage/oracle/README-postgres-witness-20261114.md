# PostgreSQL root witness port — hosted experiment

`otehon.postgres-witness/port` supplies `:read!` and `:compare-and-set!` for the witnessed Otehon multi-Pack importer. An explicit 64-hex store ID selects a pre-provisioned database row. Roots use a bounded canonical EDN vector encoded as bytes; reads refuse malformed/missing rows and standbys. A CAS requires the immediately next generation, nondecreasing checkpoint/tail, and matches the entire previous encoded root in one conditional `UPDATE`. The client waits for `psql` completion, uses `synchronous_commit=on`, refuses unexpected output, and never creates or repairs the row. A failed or timed-out CAS has an uncertain outcome; the importer already refuses to report a successful commit. PostgreSQL's [Read Committed semantics](https://www.postgresql.org/docs/14/transaction-iso.html) recheck an UPDATE predicate after a concurrent row update; the local concurrent test verifies this particular use.

On macOS 26.4 arm64, Homebrew PostgreSQL 14.19 and Babashka 1.12.218, `test/otehon/postgres_witness_check.sh` created a new private, Unix-socket-only test cluster. Two competing updates from the same root yielded exactly one success. The actual four-Pack importer advanced the row, and a copied older store was refused even though the unguarded reader could open it. A stopped DB was refused; after a clean DB restart, a fresh process reopened the witnessed group and checked a cross-Pack range. The cluster and its proof files were preserved, then its task-owned server was stopped. The initial start attempt used an overlong Unix socket path and failed; the rerun used a short path. No pre-existing database was used.

The DB and files were on one host; this is a real PostgreSQL CAS demonstration, **not** an independent failure domain or production qualification. The application role/service configuration and access to the primary must be trusted. `psql` uses a caller-owned libpq service configuration; secure transport, authentication, credentials, least privilege and non-rollbackable DB administration are external. A database restore or privileged writer can roll back or rewrite the witness, and selecting a stale promoted primary is not prevented here. Properly bind the configured store ID and protect all unguarded store paths. There is no automatic reconciliation after a crash, Native implementation, OS-cache-loss, or real power-loss evidence. Costs and latency have not been characterized.

For an isolated local run, make sure `initdb`, `pg_ctl`, `psql` and `bb` are on PATH, choose a **new** base and a short **new** socket directory under the task worktree, and pass the classpath, proof script and crosspack fixtures to `postgres_witness_check.sh`. The script initializes and stops only its own cluster, never deletes its files, and binds no TCP listener. `check.nix` invokes this as a hosted test; its exact-head CI result must be checked separately.
