# Hosted atomic governed receipt issuance with GiB basis — 2026-11-15

This hosted wrapper replaces the receipt sink in the pinned `gib_policy_governed_receipt.clj` fixture with the bounded file-staged atomic Forest stream. For each newly issued allow or deny execution receipt, the builder stages the preexisting signed GiB Prolly/policy basis and all data blocks together with the new request, signed execution manifest and receipt commit. The callback verifies the staged data basis, policy, Dango fixture cases and full GiB SHA, and the receipt bundle before publishing the group and its ref. Allow and deny are **two separate publications**, not one transaction. A read-only WAL check confirmed each has exactly one group and its ref in a single `:put-many` frame.

After a dedicated guest stop/start, a fresh process used the new publication store for both data and receipts, with original file source and Forest writer paths nonexistent. It verified both signed receipts, signature/policy refusal cases, missing-request refusal, and the 1,024 chunks' SHA-256 `1f7e0c0d3fefe5579e556a04f7796b7de01278916e49a6d31df864e16adf1708`. The reader used the fixture `ids.edn` sidecar for receipt and basis CIDs. Boot ID changed, and all 85 recorded files retained their preboot hashes. Both publications together took 134.25 s / 716,016 KiB maximum RSS; postboot read took 32.78 s / 530,360 KiB. This is one hosted sample of mostly-zero input with host cache uncontrolled.

The data and signed basis were created before this publication; authority decision and nonce callback are outside it. The host callback validates the candidate's full basis separately, while its receipt binding also uses the original source context before publication. Fixture issuer keys, clock, nonce and location do not constitute production trust, an independent witness, durable anti-replay or product-wide admission. There is no atomic cross-store transaction, host cache loss, Native I/O, physical power-loss, live AwaiVol or remote durability evidence. The prior read-only receipt fixture's source and its prerequisite are SHA-pinned; no hosted oracle is introduced as Native or CI fallback.

Evidence `.agent-output/gib-atomic-issued-evidence.tar.gz` SHA-256 `4018ce9f7bf8378d057331695e0f1a5e33b2104766c2256b8472ec3ab078bc56` contains guest output, timing, boot IDs, hash checks and the WAL inspector. Original stores and staging remain preserved.
