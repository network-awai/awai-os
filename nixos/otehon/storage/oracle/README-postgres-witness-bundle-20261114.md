# Witnessed hosted receipt bundle follow-up, 2026-11-14

This supersedes only the prior receipt oracle's statement that request and manifest are not persisted. The bounded overlay now stages canonical request and signed manifest bytes in the same immutable block batch as the causal receipt, before its witnessed ref CAS. After publication, the host reads the receipt, request and manifest from the witnessed backend, recomputes both CIDs, validates request/manifest binding and verifies the manifest signature before returning the acknowledgement. After PostgreSQL restart and a fresh JVM, this validation is repeated for both allow and deny receipts; withholding the request in the verifier is refused.

A CID inside a `kotoba.value.v1` value is a string, not an IPLD link: encoding a `:request/digest` CID value and calling `ipld/links` returned `[]`. Consequently, the generic bounded IPLD walk does **not** establish semantic receipt-to-request/manifest reachability. This example explicitly fetches and checks those blocks; it does not add application-aware tracing to the product ref verifier or GC, and does not establish that an arbitrary signed-basis closure is retained. A successful guarded ref CAS alone must not be represented as full semantic bundle verification.

Reproduce with the `receipt` mode of `postgres_witness_prolly_check.sh` as described in the earlier dated receipt record. Fresh `.agent-output/pg23`, PostgreSQL 14.19, Clojure CLI 1.12.5.1654 and OpenJDK 21.0.1: allow returned one row; the injected deny did not evaluate; injected publication failure returned no row or receipt ref; after clean database restart and fresh JVM both receipts, request and manifest were recovered and checked, and an omitted request was rejected. The existing fixed test keys, time, nonce, same-host witness, staged publication, unsigned Prolly data root, no Native or physical power-loss qualifications remain as before.
