# Atomic hosted receipt group/ref with a linked GiB file — 2026-11-15

`publish-atomic-ports!` adds bounded provisional CID put/get ports to the local atomic group/ref batch, and `atomic-receipt-publication-adapter` exposes the hosted receipt callback shape. Its caller-supplied verifier sees verified candidate blocks and may also read previously committed blocks from the same store. Verification occurs under the local writer lock before the single grouped WAL/root publication. Scope use after return fails. The host remains responsible for authenticating inputs and checking the complete closure; staging failures may leave orphan objects.

The real-tool hosted port proof staged two incompressible 1 MiB candidate blocks and read a previous block, refused closure failure and stale ref without changing root, published group/ref in one root update, refused leaked port use, and recovered all bytes in a fresh process. Existing storage/IPLD/Kotobase/writer suites passed 45 tests / 278 assertions; the pinned Linux job includes the port proof.

A dedicated Ubuntu ARM guest composed the actual Kotobase hosted receipt callbacks and linked GiB fixture with the new atomic adapter via `atomic_linked_gib_receipt.clj`. It checked the signed fixture location and all 1,024 chunks of the separate guest-created 1 GiB file before publication; one fixture Datalog row, three linked receipt records and nonce replay refusal passed. A writer-free fresh JVM revalidated all chunks, signatures and altered location/request controls. The committed receipt store's final WAL frame was `:put-many` with exactly the group and ref keys. Guest and host evidence archive SHA-256 `74e75c3e2ce407a4dada8bb21338e7a506172ca8a3123168685bd8e3dcb17be6`; source copies are identified by the archive manifest. The guest used hosted JVM and x86 Forest under QEMU.

The authority callback, issuer, keys, policy and clock in this fixture are not production trust. The GiB file, signed basis/frontier, nonce and receipt use separate transactions and/or stores; the fixture location points to the file and is not an IPLD link. The Datalog row is unrelated to the file. The atomic group/ref batch is <=32 MiB, not an atomic GiB stream. This run did not reboot after this receipt, and does not establish Native, independent witness, GC/fencing or physical-power-loss behavior. Older readers reject the new WAL frame.
