# Hosted governed GiB issuance with persistent nonce ledger — 2026-11-15

`gib_governed_atomic_nonce.clj` wraps the pinned product-ports receipt issuance oracle and replaces its fixture `constantly true` nonce callback with Kotobase `nonce-store/consumer`, backed by a separate local Otehon Forest store. The fixture computes the same canonical scope shape used by `governed-read/persistent-request` for its fixed tenant, principal, graph and epoch; it explicitly asserts single-writer operation.

On macOS arm64, the actual governed execution published allow and deny receipts separately through the product streamed writer, with the signed Prolly/policy basis and all 1,024 file chunks in each candidate group. Reusing the allow nonce through `governed/execute!` was refused as `:nonce-replayed`; the evaluator count stayed at one, and both nonce-store and receipt-store roots were unchanged. A fresh JVM, with the original data store and Forest writer unavailable, independently attempted to consume both recorded nonces and received `false` for each, with both roots unchanged. It also verified both receipts, request/manifest binding, signed basis, policy, Datalog and all chunks; full file SHA-256 `1f7e0c0d3fefe5579e556a04f7796b7de01278916e49a6d31df864e16adf1708`.

The write including governed replay took 150.82 s / 960,446,464 bytes max RSS; fresh-process read took 42.29 s / 609,992,704 bytes max RSS. This is one warm-cache, mostly-zero synthetic sample. The Clojure/JVM, input bundle, tool and reference overlays are described in `README-product-ports-gib-receipt-issue-20261115.md`; `nonce_store.cljk` was copied unchanged from Kotobase revision `1ff743c` as a local `.cljc` oracle overlay, SHA-256 `5dfa16f29d76c25ff243af013ef381f0cc4d1f75324f202de75c8a5a5bd73f8f`. This oracle SHA-256 is `9c17ea3e32366c26c4ae482ae661601325d00e8a04ba970e1b2e384dad50439d`. Task-local write/read script SHA-256 values are `2351beffc7382c978aea20fbd71fbf16570165d93ac57ef94e8a271b3d598781` and `67cb86854ece662b9bd91de8a057b4903c07d123403631b76e512f9fc8949b98`; scripts, logs, inputs, stages and stores are retained in task scratch. No downloads were made.

Nonce consumption, authority and each receipt publication are separate transactions, so a failure may consume a nonce without publishing a receipt. Single-writer exclusivity is an explicit fixture assumption, not distributed fencing. Keys, identity, trusted clock, location and engine encryption are fixtures. This does not establish production trust, rollback resistance, host OS-cache loss, power loss, independent nodes or Native execution.
