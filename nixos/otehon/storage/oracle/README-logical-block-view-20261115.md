# File-backed canonical logical blocks, 2026-11-15

`pack/logical-block-view` exposes the canonical logical-file manifest and its leaves by CID from a fully recovered Pack snapshot. The caller must supply the authenticated expected manifest CID; the view revalidates canonical manifest bytes, ordered leaf metadata and the expected CID against the recovered indexes. Each requested leaf is read through the file-backed range reader and rechecked against its raw CID. A valid but absent CID returns nil, malformed CID and modified bytes fail, and returned manifest bytes are copied. This view supports individual leaves up to 1 MiB; larger profiles fail explicitly. It is read-only and does not prove freshness, authorization, concurrent-GC safety or distributed fencing.

On macOS ARM / Babashka 1.12.218, `pack-store-test` passed 19 tests / 134 assertions and the existing shared logical corpus proof passed, including wrong expected manifest, changed manifest, corrupt returned block and absent/malformed CID controls. With `-Xmx512M`, `logical_block_view_gib.clj` recovered the previously guest-independent, host-created 64-Pack synthetic file from `README-gib-actual-writer.md`, pinned manifest CID `bafyreidk3dxbsrqaocvdhfr624j4n75v6ddgmyfgkyu24z3lirlg5aj4g4`, and read all 1,024 one-MiB leaves by their canonical CIDs. Each block matched the corresponding streamed source bytes; both complete SHA-256 values were `1f7e0c0d3fefe5579e556a04f7796b7de01278916e49a6d31df864e16adf1708`. One local run took 71.21 seconds with maximum RSS 136,429,568 bytes as reported by `/usr/bin/time -l`. This is mostly-zero synthetic data, with uncontrolled host cache and other activity; it is not a cold-I/O or production performance claim.

The NixOS reboot test now includes a full logical-block CID read of the guest-written GiB group after restart. Nix was unavailable locally and the new exact-head CI result is pending. The read-only view does not yet connect to the generic streamed receipt writer or Datalog authority and does not make nonce or separate refs atomic. A caller must bind the expected CID to independently authenticated evidence and manage freshness, GC and fencing. This does not establish Native, independent-node, physical power-loss or production trust qualification.
