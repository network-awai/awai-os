# Bound read-only block port and Prolly query — 2026-11-15

`open-bound-block-store` opens one strictly bound receipt ref and verifies its group catalog, all named archives and target. It implements only the Kotobase block protocol and block-read capabilities; writes fail with `:read-only`, and it advertises neither ref CAS nor batch puts. Each block batch checks the same root before and after reading and searches only the opened group. A root change requires reopening and reauthorization. The host must authenticate the root and exclude concurrent file mutation and GC; the returned handle does not pin an immutable filesystem snapshot. The existing generic block port is unchanged.

Local Babashka 1.12.218 two-Pack controls, under the workflow's `-Xmx768M`, confirmed that a CID found only in a later global group is returned by the generic port but not the bound port, bound writes are refused, and root changes before or during a batch cause `:catalog-changed`. The real tool and separate process verified all bound blocks. The existing strict-group negative proof covers a missing Pack and duplicate target in another group. Outputs and fixture data are retained in task scratch.

The hosted one-off JVM oracle `bound_prolly_query_gib.clj` opens the actual `allow` group from the preceding governed fixture through this read-only block port, restores its persisted Prolly index and executes the real Datalog query to the actual 1 GiB file CID. It verifies the fixture-signed basis, stored policy, receipt records, nonce replay refusals and full file digest. It additionally verifies all 1,024 chunks through each of the `allow` and `deny` exact groups. The receipt database and nonce lookup still use the existing hosted backend, not this block-only port. Keys, policy, authority, clock and identity remain fixtures; this is not a deployed runtime or Native query.
