# Hosted atomic GiB governed snapshot reboot experiment — 2026-11-15

The probe takes the previously issued hosted allow/deny receipts and the signed GiB Prolly/policy basis, copies their immutable blocks into one file-staged Forest group, and conditionally publishes one snapshot ref and group in one local `:put-many` WAL frame/root update. A trusted candidate callback reads the staged group, opens the signed basis and policy, checks both receipt signatures and request/manifest bindings, refuses a missing request, re-evaluates Dango fixture allow/deny and the Datalog query, and verifies all 1,024 file chunks against SHA-256 `1f7e0c0d3fefe5579e556a04f7796b7de01278916e49a6d31df864e16adf1708`.

After the dedicated guest was stopped and started, a fresh reader pointed the data backend to the new group and the original receipt store, original file source and writer to nonexistent paths. It repeated those checks successfully. A separate read-only WAL inspection established that the final frame includes precisely one group and the snapshot ref, and that both prior failed candidate stores had no published snapshot ref. Guest boot IDs differed and all 82 recorded source/store files matched their pre-reboot SHA-256 values. One candidate build and verification took 64.73 s / 654,320 KiB RSS; postboot read and verification took 26.54 s / 504,424 KiB. Input is mostly-zero synthetic and host cache uncontrolled.

The first attempt failed before publication because the test-only read adapter omitted capabilities required by Kotobase; the second failed before publication because CID enumeration omitted blocks in bounded inline Forest archives. The final probe enumerates both inline and file-backed archives. Failed staging and prior stores remain preserved.

This is an atomic **snapshot of preexisting receipts**, not an atomic issuance of the receipts, nonce consumption, authority decision or multi-store transaction. Issuer/capability keys, clock, nonce and location are fixtures. The readonly adapter advertises the existing backend's required capabilities solely to read historical receipts; its mutation methods throw. This is not a product-wide authorization gate, external authority receipt, independent witness, distributed fencing, Native I/O, live AwaiVol, host-cache loss, power loss or remote durability proof.

The task-local evidence `.agent-output/gib-atomic-governed-evidence.tar.gz` SHA-256 `94e7f1f9b55780bbc821803d75d8cdbef0b3cde6a796277d5e1155d51d48e934` includes logs, timings, boot IDs, checksums and the read-only WAL probe. Hosted local oracle only; no JVM fallback in Native or CI.
