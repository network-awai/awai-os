# Hosted signed Prolly GiB reboot experiment — 2026-11-15

The adjacent hosted probe stages an actual 1 GiB synthetic file's manifest and 1,024 chunks together with the Prolly datom identifying that manifest and an Ed25519-signed logical basis. The local atomic group/ref points to the signed basis. Its signature covers a logical commit containing the Prolly checkpoint; the physical root is checked against that checkpoint after opening the snapshot. Before publication and after a guest stop/start, the verifier checked the signature, rejected a modified signature and wrong checkpoint, queried the actual manifest CID, and verified every chunk and the full SHA-256 `1f7e0c0d3fefe5579e556a04f7796b7de01278916e49a6d31df864e16adf1708`. The post-reboot reader used nonexistent source and writer paths. All 80 recorded files retained their pre-reboot hashes and the guest boot ID changed.

One hosted measurement: write 50.20 s / 536,388 KiB maximum RSS; read 19.52 s / 495,196 KiB. The file is mostly-zero synthetic data. Guest cache was lost; host cache was uncontrolled. This is not a storage performance, physical power-loss, Native or remote durability qualification.

The issuer key is a known fixture; transaction, schema, model and admission policy roots are placeholders. The policy, signed authority and governed receipt from the separate experiment are not bound to this basis, and the verification callback is a hosted fixture rather than a product-wide admission boundary. No independent witness, distributed fencing, production authorization, Native I/O or live AwaiVol integration is established.
