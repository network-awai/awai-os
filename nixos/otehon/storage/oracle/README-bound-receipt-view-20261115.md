# Read-only bound receipt, nonce and block view — 2026-11-15

`open-bound-read-view` opens one strictly verified ref/catalog/group and captures one root state. It exposes a receipt target reader, a nonce-ref reader and the existing read-only block port. The ref and nonce readers and each block batch check the captured root before and after access. A present nonce ref is returned only if its marker block is in this exact group; no global fallback occurs. The block port does not implement ref CAS or advertise batch writes. The host must derive and authenticate the nonce scope and verify canonical marker semantics, authenticate the root, and exclude concurrent file mutation/GC. An opened handle is not a pinned filesystem snapshot, and root checks cannot detect an independently restored old root without a witness.

Local Babashka 1.12.218 proof at `-Xmx768M` verified receipt ref and nonce marker, absent and malformed nonce, rejection of a nonce marker that exists only in another group, no global block fallback, read-only capabilities, stale-root refusal and root changes injected during block and nonce reads. The existing process also published/verified the two-Pack group, ref, binding and nonce, refused replay and recovered via a fresh process without the writer tool.

The hosted JVM oracle `bound_receipt_view_gib.clj` reads both preexisting fixture receipt refs, nonce markers and receipt blocks from the corresponding bound views. It verifies marker bytes against Kotobase's canonical prepared marker, uses the existing causal receipt decoder and actual peer hydration, and checks signed basis, persisted Prolly/policy, Datalog result and all 1,024 file chunks. Both receipt groups were checked independently. Keys, scope, policy, visibility, clock and authority are fixtures. The marker-presence check is not by itself a new governed execution or a replay transaction; earlier publication/replay proofs remain separate.
