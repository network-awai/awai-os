# Hosted signed basis, policy and receipt composition, 2026-11-14

This fixture joins the prior signed-basis and governed-receipt reference executions. The 18-block Prolly policy fixture is restored and its actual transaction/checkpoint roots populate the existing Kotobase logical-commit contract. The logical commit's admission-policy root is the recovered policy CID; the fixture issuer signs the domain-separated logical root. Its physical root must equal the governed request's `:base/commit` and the policy ref. A hosted outer admission function verifies the signature, restored checkpoint and policy/basis agreement before invoking governed execution. Actual Dango verification and the recovered policy are used in the allowed query; the resulting signed causal receipt, request and signed execution manifest are stored using the witnessed Forest backend.

This is an explicit host composition, not a change to product governed-execution. The receipt names the physical basis through its request and manifest; it does **not** include the signed logical-basis envelope CID. The proof compares the witnessed named basis ref, request and policy ref; it is not self-contained evidence of an immutable receipt-to-envelope link. The basis envelope is a local composition, not a ratified wire format. Policy fixture digest is the existing injected SHA-256 hex profile; the logical signature root uses the other reference's injected CIDv1/raw profile. Keys, schema/model, clock, nonce, revocation and identity encryption remain fixtures.

Run `postgres_witness_prolly_check.sh NEW_ABSOLUTE_BASE NEW_SHORT_SOCKET ABSOLUTE_FOREST_TOOL signed-policy` with its pinned adapted inputs. Fresh `.agent-output/pg30`, PostgreSQL 14.19 / Clojure CLI 1.12.5.1654 / OpenJDK 21.0.1 on macOS arm64: after one clean PG restart and fresh JVM, invalid signature, physical root and policy inputs were rejected before evaluation or commit (both counters zero). The valid request returned one row and a signed receipt. After another clean PG restart and fresh JVM, the named basis and receipt were recovered, their basis/policy bindings checked, and issuer/executor signatures verified. This does not test a concurrent writer, OS-cache loss, Native, remote durability, real key custody or deployment.
