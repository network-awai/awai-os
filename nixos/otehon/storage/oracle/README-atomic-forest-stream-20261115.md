# Bounded atomic Forest stream — 2026-11-15

The hosted atomic stream accepts canonical CID blocks incrementally, retains at most 17 MiB / 32 blocks in its pending archive, writes CAR frames to private staging and compresses each with the pinned Forest tool. A staged block remains available through the provisional get port. Up to 64 verified archives, a target and a caller-verified closure are then passed to the existing single-WAL group/ref publisher. Input is bounded to 1 GiB + 16 MiB and 4,096 put calls. The Kotobase receipt adapter exposes the same provisional callback shape; expected generation and ref are checked under the local writer lock. Staged CAR, Forest and tool copies are deliberately retained.

The real-tool hosted test staged 18 incompressible 1 MiB blocks into two archives. It read a flushed provisional block, refused a failed closure with the root unchanged, checked scope closure, committed one group/ref WAL frame, and read all bytes in a writer-free fresh process. Existing storage/IPLD/Kotobase/writer suites passed 45 tests / 278 assertions. The real-tool proof is in the Linux CI job; exact-head CI is pending.

This is an opt-in hosted local operation with a trusted semantic verifier. It is not yet a measured GiB run, a witness, concurrent-GC safety, distributed fencing, external-store atomicity, Native, production authorization or physical-power-loss qualification. The builder may retain its own inputs, which are outside the pending-buffer bound. An I/O error after root publication can be ambiguous; callers must read back. Older readers reject the grouped WAL frame.
