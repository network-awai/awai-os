# Hosted atomic 1 GiB stream and guest reboot — 2026-11-15

A dedicated Ubuntu ARM Lima guest ran Otehon source `d858c704fd648621c94b8575ecf91cf562e6bae7` using OpenJDK 21 `-Xmx768m` and pinned x86-64 Forest 0.39.0 under QEMU user. `atomic_stream_gib.clj` read a previously verified guest-created synthetic logical file one 1 MiB chunk at a time, staged 1,024 chunks plus its canonical manifest, and validated all chunks before publishing 61 Forest archives and the manifest ref in one local `:put-many` WAL frame/root. Manifest CID was `bafyreidk3dxbsrqaocvdhfr624j4n75v6ddgmyfgkyu24z3lirlg5aj4g4`; the complete bytes hashed to `1f7e0c0d3fefe5579e556a04f7796b7de01278916e49a6d31df864e16adf1708`.

After guest stop/start, boot ID changed from `b66472d5-2b4c-4330-82ab-e63986057c5d` to `3d7f2448-3f43-48d0-800d-cad94e961b17`. The first task-data operation was a fresh writer-free JVM read from the new store only; it verified all 1,024 blocks and the same full SHA. Eighty source/store files matched a preboot hash manifest. Withholding one committed archive caused a missing-object refusal; appending a byte caused a digest/size refusal. The original object was restored after each control and the manifest matched. The guest and host evidence archive SHA-256 is `8495f2652b670d4b30adf350e69cea6ac77be2b0bb4300b7e1bb4fdec219929a`.

Record-only measurements: the mostly-zero synthetic input took 38.176 s inside the writer operation, 47.47 s process wall time and 532,892 KiB maximum RSS as reported by GNU time. The postboot reader reported 16.118 s internally, 17.78 s process wall and 477,932 KiB maximum RSS. Staging occupied 1.1 GiB and the final store 320 KiB on this highly compressible input. These are not general throughput, memory-peak-across-all-processes, production or hardware claims.

The caller's closure verifier is fixture code; this run does not include the Datalog/authority/receipt transaction, a witness, concurrent GC or distributed fencing. The source and output stores are separate; the output group and manifest ref alone share a single root. This validates guest OS cache loss, not host cache loss or physical power interruption. It is hosted JVM and emulated x86 Forest, not Native. This GiB experiment is not a CI gate; the 18 MiB atomic stream proof is in the Linux CI job.
