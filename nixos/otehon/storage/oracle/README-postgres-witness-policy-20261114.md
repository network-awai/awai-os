# Witnessed Prolly policy and Dango — hosted JVM oracle

On 2026-11-14 a fresh, local PostgreSQL 14.19 Unix-socket cluster and the actual pinned Forest tool stored the 18-block policy/Prolly fixture through the witnessed Kotobase block/ref backend. The caller-supplied bounded IPLD closure verifier checked the ref. After a clean DB restart, a separate OpenJDK 21.0.1 / Clojure 1.12.5.1654 process reopened the witnessed basis, reconstructed the policy from the persisted snapshot, ran the actual Datalog join and verified a Dango presentation using deterministic test Ed25519 keys.

The persisted policy CID was `bafyreidttvee6r2pduhuwto6ft4xmolglspprk4sseuhorsdpbchbswkuu`. The valid fixture returned one row. Wrong resource/basis, expired grant, modified seal and fixture revocation each returned zero rows, with respective Dango denial reasons `:dango/not-covered`, `:dango/expired`, `:dango/bad-seal`, and `:dango/revoked`. This driver applies the policy's visibility filter to the query; it does not demonstrate that an actual product admission layer suppresses evaluation or external effects on denial.

`postgres_witness_prolly_check.sh` accepts an optional fourth argument `policy`; it verifies all 200 adapted classpath files against `prolly_forest_writer_inputs.json`, separately checks the bounded CBOR/IPLD overrides and tool, and pins the policy fixture SHA-256 `0ea6a8f7b6d2086a2a6565f9a787fcac316d7bb18b5856cdb6bf935df477b0ed`. It creates a new private cluster and output, restarts only that DB, then runs `postgres_witness_policy.clj` in separate write/read JVM processes; files are retained and the server is stopped. This is a one-off hosted oracle, not a Native gate or fallback.

The caller supplies the bounded closure verifier, fixed clock, revocation set, test keys, identity encryption and synthetic blinding. This does not establish signed data basis, a durable receipt, trusted key custody, nonce/revocation distribution, production policy admission, independent witness, OS-cache loss, power failure or Native qualification. Policy and block/ref state are persisted but not deployed to the live AwaiVol.
