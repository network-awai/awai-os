# Persisted frontier and fresh causal receipt: hosted oracle

On 2026-11-14, `persisted_frontier_receipt_write.clj` connected the already-persisted signed Forest frontier in `README-signed-frontier-forest.md` to the existing bound admission and causal receipt writer. It explicitly verifies the fetched Ed25519 fixture proof and its checkpoint/policy before accepting the unchanged persisted frontier, then uses the existing Dango fixture policy and Datalog query and publishes a signed causal receipt, request, signed manifest and location blocks into a new Forest store. The fixture uses a distinct fixed nonce `fixture-persisted-frontier-20261114`: the resulting new receipt CID was `bafyreia3yjhietadsi7j5obynsfsblbw6yicw4gsj56vivcchd6t2dfaxm`, and its causal commit CID was `bafyreigene4dpmobe5y7w2cxwtdmpdgfmx6rqqtv2cnrzrnmazdpjcv27i`. The query returned the expected fixture row.

The existing negative controls rejected substituted location, changed checkpoint, wrong policy, missing proof and wrong proof bytes before nonce/authorization/evaluation/commit. An injected Forest publication failure withheld the query result. A separate JVM ran `persisted_frontier_receipt_read.clj`, reopened the frontier and newly published receipt, verified the frontier signature and same-epoch fork rejection, and revalidated receipt, request, manifest, location, proof binding and signatures. An independently copied receipt store with one Pack withheld failed with `committed Forest archive is missing`; the original and the withheld Pack remain intact. The first attempt at combining the two reads terminated Clojure's agent executor too early; the corrected reader suppresses the intermediate shutdown. Earlier attempt outputs are retained.

The scripts use the staged hosted oracle classpaths, the saved signed-basis and frontier stores, the pinned Forest tool, and a new task-owned receipt output. Environment and source pins are as in `README-signed-frontier-forest.md` and `README-proof-location-receipt.md`. JVM is a local Otehon oracle, not CI or Native fallback. The fresh output is `.agent-output/persisted-frontier-receipt-02` and the negative copy is `.agent-output/persisted-frontier-receipt-missing` in the originating worktree.

This is an actual new store publication and a distinct content-addressed fixture receipt, but keys, nonce and clock are test fixtures; the nonce callback is not durable replay protection. The guard is assembled by the oracle, not the shipped product. Frontier, source proof and receipt use separate groups/stores, with no cross-store transaction; TOFU and local CAS cannot prevent a whole-store rollback. These process restarts do not establish OS-cache loss, physical power loss, Native behavior, independent-node durability or production qualification.
