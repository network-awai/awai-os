# Full hosted Forest writer crash proof, 2026-11-14

This exercises `put-file-large!` itself, including source chunking and compression, not only import of prepared archives. A dedicated synthetic 1 MiB old file is replaced with a different synthetic 17 MiB file comprising two Forest Packs. The test kills a real child process at seven observer boundaries: first and second Forest file half-written, WAL half-written and renamed, and root half-written, renamed and directory-synced. It copies the durable-looking store files to a fresh directory, opens them in a fresh process, requires the complete old or complete new group and verifies every restored byte against the original SHA-256. The second-Forest failure is also retried through the full writer and the new bytes are independently read back. No original data is deleted.

Babashka 1.12.218, pinned Forest tool SHA-256 `e5fb23076a46c055142b3dbf3efa1ad5a68532d14419ad9994785986719b205f`, macOS arm64, fresh `.agent-output/full-writer-crash-03`: seven of seven cases passed. Pre-root-publication points recovered the old 1 MiB; root-rename and directory-sync recovered the complete 17 MiB / two Packs. This records process-kill behavior and copied-file recovery, not loss of OS cache, a machine restart, actual power interruption, native I/O, concurrent writers or a remote failure domain. An earlier 1 GiB proof is separately recorded in `README-gib-actual-writer.md`; this crash run does not demonstrate a 1 GiB crash.

The existing Linux hosted Forest writer CI job runs the same script using its pinned Linux Forest tool and Nix-pinned Babashka. CI results are separate from the local macOS result.
