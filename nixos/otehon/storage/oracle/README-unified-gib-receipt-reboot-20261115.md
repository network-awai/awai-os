# Hosted unified GiB and receipt reboot experiment — 2026-11-15

On the dedicated `awai-linked-recovery-174` Lima guest (Ubuntu, 3 GiB RAM), the pinned Kotobase AWAI-174 fixture was adapted by the adjacent scripts to stage a 1 GiB synthetic, mostly-zero file (1,024 × 1 MiB blocks), its logical manifest, and request/execution/receipt blocks in one Otehon atomic stream group. Its closure verifier re-read every candidate file block before publication. A single local `:put-many` WAL frame published the group and receipt ref.

After the guest was stopped and started, a fresh reader without the Forest writer fetched all 1,024 blocks from that committed group and verified SHA-256 `1f7e0c0d3fefe5579e556a04f7796b7de01278916e49a6d31df864e16adf1708`. It verified the signed authority and location and rejected wrong tenant, wrong request, altered location, and bad authority signature. The receipt commit and file manifest were present in the same 61-archive group selected from that frame. All 225 recorded source and store files matched their pre-reboot SHA-256 values; guest boot ID changed.

Guest `/usr/bin/time -v`: write 58.80 s, maximum RSS 738,412 KiB; post-reboot read 32.17 s, maximum RSS 723,684 KiB. This is one synthetic sample including fixture verification, not a storage benchmark or qualification. The compressed data are unusually sparse and the host's OS cache was not cleared. Initial pre-reboot file and receipt checks succeeded but an additional assertion incorrectly assumed there was only one group; the revised check identifies the group from the publication frame. The revised pre-reboot and reboot checks passed.

The authority, basis, nonce and signed-location source remain separate stores or transactions; the signed location references the preexisting source store and uses a CID string. The reader still opens source metadata to reconstruct the fixture. The Datalog row is not connected to the file. This is fixture authority and hosted JVM/QEMU Forest I/O, not production authorization, independent witness, distributed fencing, Native, real power loss, or `/Volumes/AwaiVol` integration. No remote durability is established.
