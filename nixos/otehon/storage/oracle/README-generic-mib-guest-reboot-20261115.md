# Generic 1 MiB blocks across guest reboot — 2026-11-15

On a dedicated Ubuntu ARM Lima guest, Otehon source `3edda3c95c08005bf058b4d6fbabb6f6b956a518`, OpenJDK 21 with `-Xmx512m`, pinned x86-64 Forest 0.39.0 under QEMU user, and `generic_large_block_proof.clj` wrote two deterministic incompressible 1 MiB blocks through the generic Kotobase block store. After guest stop/start, the first task-data read ran in a fresh JVM with a nonexistent writer executable and compared both full blocks successfully. Boot ID changed from `9b509f3d-d664-4ff4-8749-46df92ec8aa7` to `569cf3c0-b0cc-46f5-9b26-e61289cf8eab`.

A 21-file source/store hash manifest matched after reboot. Withholding a task-owned archive made another fresh read fail with the missing Forest object error; the archive was restored and the manifest matched again. Guest and host copies of the evidence archive have SHA-256 `9a970e21dffcc69dfa67ae68ee888027fd07e6cfc72d65228af7255b2bedce19`. The first archive command used shell brace expansion under `sh` and failed after restoring the object; a corrected archive command succeeded. Source/proof hashes matched the host copies.

The NixOS guest reboot gate now performs the same generic writer/read and missing-archive checks. Local Nix evaluation was unavailable because `nix-instantiate` is not installed; exact-head CI must validate the Nix test. The observed run is a hosted JVM and emulated x86 Forest experiment, not Native I/O. The guest reboot clears guest OS cache but does not prove host cache loss, actual power failure, independent witness or cross-store atomicity.
