# Logical-file read port for Kotobase — 2026-11-15

`open-logical-read-store` composes a recovered, caller-authenticated logical-file view with another Kotobase block store as a read-only block port. File manifest and chunks are checked first; missing CIDs are requested from the base store. An invalid CID or corruption in a selected file chunk is an error, not a reason to fall back. The adapter refuses every write and does not expose refs. The caller remains responsible for authenticated expected manifest, authorization, freshness, concurrency and GC. It is not an atomic transaction across the stores or an adapter for writing 1 MiB blocks.

On macOS ARM with Babashka, `logical_product_proof.clj` passed against the four-Pack / 2 MiB shared corpus, including manifest, chunk, base fallback, bad CID, write refusal and a corrupted selected chunk that must not reach the fallback. `otehon.kotobase-forest-blocks-test` passed 7 tests / 47 assertions. Against the previously generated synthetic GiB store, `logical_overlay_gib.clj` recovered the manifest and read a full 1,048,576-byte first chunk via the Kotobase block interface; its CID matched, and writes were refused. The initial invocation of this local oracle failed before reading because `dir` conflicts with a Babashka REPL binding; renaming the variable fixed the script. This is hosted Otehon, not Native, real policy, an all-chunk scan, cold read or benchmark.

The existing generic writer still admits at most 850 KiB per block: its archive, decoder and store bounds all require a coherent versioned extension before a canonical 1 MiB chunk can be written via that generic path. The logical writer and read overlay do not make separate authority, file and receipt stores atomically publishable.
