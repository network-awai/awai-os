# Receipt-to-proof location binding: hosted experiment

On 2026-11-14, this local reference extended `README-signed-basis-receipt.md`. The fixture creates a codec-encoded, CID-addressed location record containing the recovered signed basis proof CID, physical basis and actual policy CID. It signs an existing v1 ExecutionManifest whose `:location/manifest` is the location record CID. The existing governed execution and causal receipt sink sign a receipt referencing that manifest. The outer adapter persists receipt, request, manifest and location blocks into a Forest group and reads the receipt back before returning rows.

A separate JVM recovered the signed data group and the receipt group. It verified the signed basis and frontier using the previous reference, recovered and checked the request, receipt, manifest and location CIDs, verified issuer and executor Ed25519 signatures, and checked the links receipt → signed manifest → location → expected proof, physical basis and policy. A changed proof in the location without changing the manifest CID failed; changing the manifest CID without a fresh valid issuer signature also failed; a different externally expected proof failed. An injected Forest write failure withheld rows. The allowed Datalog query returned one fixture row.

This location record is an experiment, not a canonical location schema or shipped product admission rule. The helper explicitly checks a separately supplied expected proof; the product does not yet enforce that check before query. The proof and receipt remain in separate groups, and the receipt sink uses in-memory staged blocks and refs. Keys, authority, time, schema, encryption and transaction history remain fixtures. No Native, OS cache loss, power-loss, fencing or production qualification follows.

Use the inputs in `README-signed-basis-receipt.md`: set `SIGNED_BASIS_OUTPUT` to the prepared signed group, `GROUP_FOREST_STORE` to its `store` directory, `FOREST_TOOL` to the pinned tool, and `CAUSAL_RECEIPT_OUTPUT` to a new empty private directory. With the same Clojure CLI 1.12.5.1654 adapted classpath, run `proof_location_write.clj`, then `proof_location_read.clj` in a fresh process. The output and staging are retained. No additional dependency download was needed.
