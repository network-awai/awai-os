# Receipt-to-proof location binding: hosted experiment

On 2026-11-14, this local reference extended `README-signed-basis-receipt.md`. The fixture creates a codec-encoded, CID-addressed location record containing the recovered signed basis proof CID, physical basis and actual policy CID. It signs an existing v1 ExecutionManifest whose `:location/manifest` is the location record CID. The existing governed execution and causal receipt sink sign a receipt referencing that manifest. The outer adapter persists receipt, request, manifest and location blocks into a Forest group and reads the receipt back before returning rows.

A separate JVM recovered the signed data group and the receipt group. It verified the signed basis and frontier using the previous reference, recovered and checked the request, receipt, manifest and location CIDs, verified issuer and executor Ed25519 signatures, and checked the links receipt → signed manifest → location → expected proof, physical basis and policy. A changed proof in the location without changing the manifest CID failed; changing the manifest CID without a fresh valid issuer signature also failed; a different externally expected proof failed. An injected Forest write failure withheld rows. The allowed Datalog query returned one fixture row.

Observed CIDs: proof `bafkreigfbzgc3xh4uel37eg7msupniof57qzp2kp6jo3yg2mpo3vepw55a`, location `bafyreigi5t2hvtaw7fg6e62g4ioj3jfhc5p6ynua7wkmcooex4zayojxxi`, manifest `bafyreidqx7cwbvan7ljpzhx5icn63ad3f7tyort45p5jmyj7lg65wzgtgm`, receipt `bafyreiarksimcuhpb6hj4kj3n22wloml5a62m5hqeph57jwhstcwwt5vqu`. The proof CID printed by the earlier `signed_basis_receipt_read.clj` on the same saved data and receipt fixture is also the proof CID above; the earlier README's proof string differs. That earlier README is left untouched pending correction review.

This location record is an experiment, not a canonical location schema or shipped product admission rule. The helper explicitly checks a separately supplied expected proof; the product does not yet enforce that check before query. The proof and receipt remain in separate groups, and the receipt sink uses in-memory staged blocks and refs. Keys, authority, time, schema, encryption and transaction history remain fixtures. No Native, OS cache loss, power-loss, fencing or production qualification follows.

Use the inputs in `README-signed-basis-receipt.md`: set `SIGNED_BASIS_OUTPUT` to the prepared signed group, `GROUP_FOREST_STORE` to its `store` directory, `FOREST_TOOL` to the pinned tool, and `CAUSAL_RECEIPT_OUTPUT` to a new empty private directory. With the same Clojure CLI 1.12.5.1654 adapted classpath, run `proof_location_write.clj`, then `proof_location_read.clj` in a fresh process. The output and staging are retained. No additional dependency download was needed.

## Bound execution entry-point follow-up

On 2026-11-14, `proof_location_admission_write.clj` used `execute-bound!` from Kotobase draft PR #101 commit `30f65d4f44b448577cb9d2e193751abb0b1098cb` (source and staged `.cljc` SHA-256 `f2c00351d2d22fd03945ff903e981f719e131dd53463d1208f10d3be77b18164`). It overlaid that single source before the prior adapted Kotobase classpaths. The caller-provided fixture admission read the proof from the recovered Forest group, recomputed its CID, verified the logical signature/checkpoint and actual policy CID, and checked the fixture location's manifest binding. The real governed read and causal sink returned one query row after writing the signed receipt; a separate JVM reopened the two groups and revalidated the receipt-to-proof binding.

Altered location/proof/policy, missing proof and wrong fetched proof bytes were rejected in admission before the instrumented nonce, authorization, evaluation or receipt functions ran. The injected sink publication failure still withheld rows. The missing/wrong bytes were injected at the fetch boundary; the positive proof came from the actual stored group. An intermediate run using `assert` for the missing proof escaped as an `AssertionError`; the fixture now explicitly throws `ExceptionInfo`, and the complete final run passed. Intermediate output remains retained.

To reproduce, prepare the same classpaths and data as above, add a first classpath entry containing the pinned Kotobase `governed_execution.cljk` copied to `kotobase/governed_execution.cljc`, and run `proof_location_admission_write.clj` with a new empty private output, then `proof_location_read.clj` in a fresh process. This is a caller-supplied test verifier with fixture EDN, test keys, a fixed clock and in-memory location data. It is not the product verifier, a standardized proof/location schema, secure frontier persistence, Native I/O, OS cache loss, or production qualification. Proof and receipt are still in separate groups.
