# Hosted GiB signed basis and persisted policy reboot experiment — 2026-11-15

The hosted probe persists a protected `:file/logical-cid` datom and the `:file/` read policy in the same Prolly snapshot as an actual synthetic GiB file's manifest and 1,024 chunks. Its logical commit includes the transaction receipt's tx root, the snapshot checkpoint and recovered policy CID; a fixture Ed25519 issuer signs that commit. The single local atomic Forest group/ref points to this signed basis. The Kotobase signed-basis verifier restores the checkpoint and checks signature and expected policy CID. The verifier explicitly accepts the physical-location callback as a fixture.

Before publication and after dedicated guest stop/start, the verifier recovered policy and signed basis, rejected a bad signature and different policy CID, and evaluated Dango tokens scoped to the actual physical basis. A valid fixture grant permitted the protected Datalog result; a token for another resource produced a denied decision and no visible result. The allowed row resolved the stored manifest and all 1,024 blocks, matching SHA-256 `1f7e0c0d3fefe5579e556a04f7796b7de01278916e49a6d31df864e16adf1708`. Postboot source and writer paths were nonexistent. Boot IDs differed and 80 recorded files retained their pre-reboot hashes.

The write took 63.47 s / 565,436 KiB maximum RSS; the read took 21.57 s / 488,020 KiB. These are single hosted samples with mostly-zero input and host cache uncontrolled. Guest restart loses guest cache only. Issuer seeds, capability root, clock, schema and model are fixtures. The deny check exercises Dango and policy filtering in the test callback; it does not establish the product's full governed admission boundary or prove no unauthorized index reads. No governed execution receipt is bound to this signed basis; witness, Native, live AwaiVol, host cache loss and remote durability remain open.

Task-local evidence `.agent-output/gib-policy-prolly-reboot-evidence.tar.gz` SHA-256 `8c099bb23d089710bdba565ea48e586d879a57ac845c2521e66a34558b06c9c7` contains the probe, outputs, timings, boot IDs and checksum comparisons. Original guest data and staging are preserved. The dedicated VM disk was increased from 16 to 24 GiB for retained staging; host disk remains separate. No JVM oracle is added to Native or CI.
