# Signed basis with a persisted Forest frontier: hosted oracle

On 2026-11-14, `signed_frontier_forest.clj` connected the Kotobase draft PR #101 `a1caf89acd99dfbd83c73874eae19ebc5a39df95` hosted frontier adapter (source SHA-256 `c7c5b1b0c4798ea027de9493aae859ec99e3713ab1b7ca5da2dd38074e29441f`) to Otehon's composed Forest `IBlockStore`/`IRefStore` and the existing two-Pack Ed25519 signed-basis fixture. It used the bounded canonical value codec from Kotoba draft PR #1339 `cc94fa4513382cbd9411ec67805dd5feccb851e2` and the existing pinned macOS Forest tool SHA-256 `e5fb23076a46c055142b3dbf3efa1ad5a68532d14419ad9994785986719b205f`.

One JVM explicitly initialized the frontier after verifying the actual fixture signature, checkpoint and policy CID. A bad signature was rejected before the store root changed. The frontier block and ref were published through the real Forest ports; the saved canonical frontier CID was `bafyreickd2ozq5pp5sq6mfetq6gqbvck7ikmspcwkgyomg4ke4wafask7a`. A fresh JVM reopened the store, verified the original signature, recovered the same frontier, and refused a different *validly signed* same-epoch fixture fork without changing it. In a separate copy, removing the frontier's Forest archive failed with `committed Forest archive is missing`; the original and withheld archive were retained. The first attempt failed before publication because the private stage directory was missing; the corrected attempt used a fresh output.

`persisted_frontier_admission_replay.clj` then used that recovered frontier to gate a read-only replay of the existing signed proof, fixture Dango policy, Datalog query and already-saved signed causal receipt. The successful event order was `[:basis :nonce :authorize :evaluate :readback]`; changing the proof checkpoint was rejected with only `[:basis]`. The freshly fetched proof is explicitly signature-verified even on an unchanged frontier because `accept-head` intentionally does not reverify an unchanged head. The receipt was only reread and checked; no new receipt was published.

Run each script with the existing signed basis group, the private output and the adapted oracle classpath under `.agent-output`; the exact paths and generated state remain in this worktree. The first script accepts `write` or `read`, and `read` must run in a fresh JVM. The replay also needs `GROUP_FOREST_STORE` set to the signed-basis store and `CAUSAL_RECEIPT_OUTPUT` to the previously saved bound-admission receipt. The JVM is a local Otehon reference oracle, not a Native runtime or CI fallback. No dependency downloads were needed for these runs.

The verifier and query admission are supplied by the experiment, not wired into the product. Issuer keys, authority, nonce/time, schema and transaction roots remain fixtures. TOFU initialization and a local ref do not prevent rollback or deletion of the entire backing store; ref CAS has only its declared single-writer scope. This is process restart, not OS cache loss, physical power loss, independent-node durability, native qualification or production acceptance.
