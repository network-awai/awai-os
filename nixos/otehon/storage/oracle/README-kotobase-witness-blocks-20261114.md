# Witnessed Kotobase Forest block port — hosted experiment

`open-witnessed-block-store` exposes an explicit `IBlockStore` for a store governed by a prepared witness. It verifies the supported Pack/IPLD root and checks the witness before and after reading blocks; a pending, changing or mismatched witness refuses the result. Writes use the existing generation-fenced witnessed Forest group writer. Ambiguous writes are not retried as successes. Even empty operations check the witness; existing unqualified block/backend APIs are unchanged.

On macOS 26.4 arm64, a task-owned PostgreSQL 14.19 Unix-socket instance and the pinned Forest tool (`e5fb23076a46c055142b3dbf3efa1ad5a68532d14419ad9994785986719b205f`) saved and read 20 fixture CID/byte pairs through the actual Kotobase block port. The proof also checked idempotent repeat, refusal when witness changes during a read, refusal of pending operations, pre-CAS interrupted publication followed by verified reconciliation, stale local root refusal and refusal of an unknown catalog namespace. The DB server was stopped; task artifacts are retained. These are same-host hosted tests, not a separately trusted node or Native execution.

This is a block-only port: no witnessed Kotobase ref CAS, ref-closure verifier, composed transactional backend, signed-frontier admission, real policy or receipt is supplied here. Every writer must actually use the witnessed protocol, the database and its service must be independently trusted and rollback resistant, and the local lock does not provide distributed fencing. Root verification and repeated witness checks add unmeasured I/O cost. The existing Linux real-tool CI exercises the optional PostgreSQL proof; check exact-head results independently. OS-cache loss, hardware power loss and production qualification are not established.
