# Streamed 1 MiB blocks across guest reboot — 2026-11-15

The actual hosted `publish-streamed-ports!` path wrote five deterministic incompressible 1 MiB CID blocks in two independent batches. The verifier-failure control left the ref absent while already flushed blocks remained accessible as orphans; retry published the ref, and a stale ref CAS was refused without changing the root. A separate reader verified the ref and all five bytes/CIDs. The local Babashka proof also passed with `-Xmx512M`.

On the dedicated Ubuntu ARM guest, source `3edda3c95c08005bf058b4d6fbabb6f6b956a518` (unchanged storage code at `98dd637`) ran the same proof using JVM `-Xmx512m` and pinned x86 Forest under QEMU. After guest stop/start, boot ID changed from `569cf3c0-b0cc-46f5-9b26-e61289cf8eab` to `dd1c1347-a30a-47ad-8dba-fefcc73b91d4`. The first task-data read in a fresh process, with no writer executable, verified both batches, ref and all five blocks. Fourteen store/proof files matched preboot hashes; withholding one archive caused a missing-object refusal. The archive was restored and the hash manifest matched again. Guest and host evidence archive SHA-256 `42f7bd72961138cb8c77756bfe24cf376110f7a696d573d7db00b7b849dc5420`; proof SHA-256 `9ddfee52ea6c44d9c2856e2d8f9a3052b553e8c384cfe62b1716336b03507f30` matched both copies.

The real-tool and NixOS reboot CI jobs now include this proof. Local Nix is unavailable, so exact-head CI still needs to run. Batch writes precede ref CAS and are separately visible/orphanable; this is not an atomic transaction across batches, authority, nonce and receipt, nor a proof of concurrent GC safety or distributed fencing. Guest cache loss is not host cache loss or physical power failure; this is not Native I/O or production policy.
