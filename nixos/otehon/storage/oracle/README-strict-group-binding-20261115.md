# Opt-in exact group binding — 2026-11-15

An isolated reproduction found that the existing Kotobase block port intentionally searches `kotobase-blocks/` groups in order. If group `a` and the later group `z` both contain the receipt target CID, but another Pack in `z` is removed, explicit `z` recovery rejects `:missing-forest` while the global CID port can still return the target from `a`. Its bytes remain CID-verified; the gap is that a ref containing only a CID does not establish that the physical group published with it is intact. Do not treat a successful global lookup as verification of a specific group.

The optional bound form of `publish-file-group-and-ref!` now stores a v1 physical management record with ref, group name and SHA-256 of the exact persisted group catalog in the same root/WAL frame as the group and ref (and optional nonce). Its trusted closure verifier still must verify the complete required DAG using the supplied candidate-only getter. `recover-bound-ref` refuses missing legacy bindings, malformed/mismatched records, changed catalogs, missing/corrupt Packs and missing target without searching other groups. It checks that the group was recovered against the same root snapshot. An unbound call through the group/ref publisher cannot overwrite a bound ref. The record is physical metadata, not a new canonical content CID or a signature.

`strict_group_binding_proof.clj` uses two prebuilt Forest files and a synthetic nonce marker. It checks failed closure leaves root unchanged; successful group/ref/binding/nonce share a single frame; unbound overwrite is refused; a replaced catalog is refused; and after restoring the catalog, removing its second Pack is refused by strict recovery even though legacy global lookup can still obtain the duplicated target from the other group. Root stays unchanged during the missing-Pack check. A nonexistent/legacy binding is explicitly refused. Local Babashka 1.12.218 passed; the existing IPLD Forest suite also passed 13 tests / 102 assertions. The source and fixture outputs are retained in `.agent-output`. Nix was unavailable locally; this proof is included in the Otehon Nix check and exact-head CI is separate.

Source SHA-256 `8002d7403e2cb1f986d5233bbd0d63a9af26dceb159f2de9340fc668a7b916bf`; proof SHA-256 `19c115c7fe426d91ba3dc1ee2826dea544204c436bf272b4dcf19854d422b756`. Two earlier exploratory attempts failed before the final reproduction: one pre-created a directory owned by `store/init!`, and one used group names outside the block-port namespace. The successful isolated reproduction and proof use fresh task-owned directories.

This is an opt-in lower-level primitive: the streamed governed receipt adapter and existing global block port have not yet adopted it, existing refs are not migrated, and a returned handle is not pinned against later mutation or GC. Direct legacy ref/group operations can invalidate a binding, which strict recovery detects; same-identity hostile mutation, external witness/anti-rollback, authenticated authority, production policy, Native and power-loss durability remain open. Explicit migration and closure verification are required before relying on this as the default.
