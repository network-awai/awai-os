# Witnessed generic IPLD Forest writer — hosted experiment

The bounded `put-ipld-blocks!` writer has an explicit eight-argument, generation-fenced witnessed form. It checks the witness before staging and requires the complete supported Pack/IPLD root verifier before and after publication. Its generic lower-level publication form takes an explicitly trusted verifier; an incomplete or permissive caller-supplied verifier cannot qualify a root. Unknown root namespaces, including Kotobase refs, remain refused. The six- and seven-argument legacy forms are unchanged and are not witnessed.

On macOS 26.4 arm64 with Babashka 1.12.218, the pinned Forest tool SHA-256 `e5fb23076a46c055142b3dbf3efa1ad5a68532d14419ad9994785986719b205f` generated two archives containing 20 CID/byte pairs from the existing Prolly/policy fixture plus two seeded blocks. The atom-witness writer proof recovered and checked every pair. A second local run used the same actual tool with the isolated PostgreSQL 14.19 witness: an injected exception before CAS left a persisted prepared intent, guarded open refused it, explicit Pack/IPLD root reconciliation completed, and all 20 CID/byte pairs reopened. The server was stopped; fixtures and staging are retained. Separate prebuilt two-archive PostgreSQL tests cover the same prepared-intent transition. The fixed Forest tool is an Otehon host program, not Native I/O.

The `forest-writer-linux` workflow includes the atom-witness actual-writer proof and a combined actual-tool plus PostgreSQL isolated-cluster proof. `check.nix` includes the prebuilt two-archive PostgreSQL and unit tests. Check the exact-head CI separately. These are local/same-host test witnesses, not independent-node durability, signed authority, Kotobase ref/closure qualification, OS-cache-loss, power-loss or production acceptance. Full Prolly query, real policy and signed receipt integration are still separate work.
