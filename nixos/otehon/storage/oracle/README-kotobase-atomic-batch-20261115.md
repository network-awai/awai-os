# Hosted Kotobase atomic block batch and ref — 2026-11-15

`publish-atomic-batch!` now takes canonical CID blocks, uses the real Forest writer to build a bounded file-backed archive group, validates the candidate closure through a required host callback, and conditionally publishes that group and its Kotobase ref together in one local `:put-many` WAL frame/root. The expected ref and an observed generation are checked under the local lock. Failed validation can leave private staged files and immutable orphan objects. Existing group names cannot be replaced by different content.

The real-tool hosted proof writes two incompressible 1 MiB blocks in two archives; closure refusal and stale ref leave the root unchanged, and a successful publication yields one group and one grouped WAL frame. A fresh process with no writer tool verifies the ref and both complete blocks. Babashka `-Xmx512M` passed; storage, IPLD, Kotobase Forest and writer regressions passed 45 tests / 278 assertions. The real-tool proof is included in the Linux CI job. This extends the earlier lower-level `README-generic-atomic-group-ref-20261115.md`, whose statement that the group/ref API was not wired to a block writer applied at that time.

This is an opt-in bounded <=32 MiB in-memory batch, not the streamed transaction builder and not atomic across independent stores. The host must authenticate the inputs and validate the full required closure; witness, concurrent GC, distributed fencing, Native, a GiB atomic batch and power-loss qualification remain open. Older readers reject the new WAL frame.
