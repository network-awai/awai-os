# Strict nonce binding: hosted GiB recovery (2026-11-15)

The hosted probe `bound_receipt_view_gib.clj` was updated to use the product's strict per-nonce binding on publication and recovery. Awai source was frozen at PR #124 commit `1f829e6`. The governed fixture and its policy probe were SHA-256 pinned to `b396c68621caf109c500bdb307e216b082b70e170475f1b20f048975ae220896` and `e5f9226ff30272174a67223bff528f933c2f2390d8840a0ac1963ff0f25ba0a9`. Forest tool SHA-256 was `e5fb23076a46c055142b3dbf3efa1ad5a68532d14419ad9994785986719b205f`. Fixture credentials and authority are not production trust.

A fresh hosted write with Temurin 21.0.1 used 1,024 chunks totaling 1 GiB logical input. The actual Prolly query, signed basis, allow/deny policy and receipts passed; wrong policy and bad signature were refused; nonce replay left the root unchanged. Two WAL frames each contained exactly five entries: a group, receipt ref and binding, and nonce ref and binding. The write took 190.69 seconds wall clock and used approximately 2.1 GiB of temporary staging. This fixture is highly compressible: the resulting store was approximately 396 KiB, so these numbers do not qualify random/incompressible GiB storage or performance.

The first attempted separate-process read failed to compile because the older causal-commit overlay lacked `receipt-at-query`; it did not change the stored data. The second read used the independently pinned prior bound-read overlay (`causal_commit.cljc` SHA-256 `5e33441c62b5495c5acdf7910256e065d1af30f851b55dc8e53c619b9b0357e6`) and succeeded in 124.77 seconds. It used the saved store with an absent source and absent Forest writer. Strict nonce markers, unchanged root, signed basis, policy, actual Prolly query and allow/deny receipts were checked.

The saved store and pinned inputs were transferred to a dedicated Linux Lima guest (input archive SHA-256 `3d5ba5fd8e8a67921036aadbfa3b51c16ae2fb39df2d529e0c9212d2daba3a1e`). After a clean stop and restart, the guest boot ID changed from `fbdcf79f-6ab1-43f4-98e2-2a1cc9198e9e` to `afcf10e9-0289-4679-8ff2-977b11cd41c8`. OpenJDK 21.0.13 repeated the read successfully in 65.74 seconds with no source or writer present. The archive hash was verified on the guest. The host OS cache was not cleared, and a clean guest reboot is not a host reboot or physical power loss.

Evidence and exact local scripts are preserved in the task worktree under `.agent-output/gib-nonce-binding-174/`. This is hosted Otehon evidence, not Native Forest I/O, authenticated production keys, independent witness, physical failure qualification, or a performance threshold.
