# Explicit witnessed root reads (2026-11-14 UTC)

`otehon.root-witness/open-verified!` takes a host-owned, store-bound witness reader and compares its complete root identity with the local `read-store` root before opening a snapshot. It refuses degraded local state and mismatch, verifies the opened handle has that same basis, and rereads the witness before returning. `pack-store/recover-witnessed`, `ipld-forest/recover-witnessed` and `recover-group-witnessed` expose the guard. Missing, malformed, mismatched or changing witness values do not produce a handle.

The witness is a trust boundary. Its reader must authenticate a fresh, durable value bound to the correct store and lie outside the store's rollback domain. A callback supplied by an untrusted caller, an atom or a file on the same volume does not establish that property. The implementation does not provide a real witness service, a witness CAS/write protocol, reconciliation after a crash, or automatic adoption by existing read APIs. Its second read narrows a race during open; a previously returned snapshot is not revoked by subsequent witness changes. The ordinary unqualified recovery API still reproduces the valid-stale-root counterexample and must not be represented as rollback-protected.

Local Otehon Babashka 1.12.218 tests create actual store and Forest fixture data and use a test-only atom as witness. They verify successful Pack/single Forest/group open, rejection of missing and mismatched witness, rejection if the witness changes during open, and refusal of the exact valid generation-1/2 pair restored after generation 3. In that last case the unqualified Pack API is explicitly observed returning `old`. The six related suites passed 54 tests / 325 assertions. These are local fixture results, not an independent witness, Native, process/OS restart, power-loss or production qualification. Existing root slot and legacy compatibility limitations remain.
