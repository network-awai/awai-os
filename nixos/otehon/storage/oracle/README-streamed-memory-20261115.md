This record supersedes the two-batch configuration described in `README-streamed-publication-20261115.md` for the current candidate, while retaining that earlier measurement as historical evidence.

The streamed path now flushes at most 4 MiB per batch, while keeping the same explicit total limits, full semantic verification, and single ref CAS. With Babashka 1.12.218 on macOS ARM and `-Xmx512M`, 15 tests / 108 assertions passed. The pinned Forest tool wrote 41 mostly-zero 820 KiB blocks (34,426,880 logical bytes) across 11 immutable batches; `/usr/bin/time -l` reported 91.98 seconds and 489,603,072 bytes maximum RSS for the measured process. A separate writer-free process verified every block and the ref in 33.63 seconds and 328,810,496 bytes maximum RSS. These measurements are local single runs; they do not include a full concurrent-system memory accounting or establish a threshold. An isolated copied store with an archive withheld failed with `:missing-forest`. The two task-owned writer runs each retained approximately 746 MiB, including repeated staged tool copies; their storage overhead is material to scaling and has not been optimized.

The NixOS test wrapper now sets `-Xmx512M` and explicitly removes the writer tool from both streamed and scoped reads. Nix was unavailable locally, so the new exact-head NixOS CI result remains unverified; neither the local RSS nor a smaller flush alone proves that the 1 GiB guest will pass.

Separately, a valid canonical raw 1,048,576-byte block was refused by the current streamed blockstore with `:too-large` before CAS because its individual-block cap is 850 KiB. Canonical logical-file v1 permits at most 1,024 chunks, so that adapter cannot directly carry a full 1 GiB file using the 1 MiB profile. The existing file-backed `put-file-large!` has a distinct 1 MiB path; neither merely raising the memory-based cap nor silently re-chunking preserves the required identity and bounded reader guarantees. A file-backed canonical block connection and its end-to-end GiB test remain open. No Native, host cache loss, physical power-loss, concurrent GC or production trust qualification is claimed.
