# Atomic local group/ref process-kill proof — 2026-11-15

The actual `publish-file-group-and-ref!` writer was SIGKILLed at seven observed points: while writing and after renaming the second Forest object; during and after writing the WAL; and during, after renaming, and after directory-syncing the root. A fresh process opened a copy of committed records. Before root rename, neither the group nor ref was visible; after root rename, both were visible and both archive-root blocks passed CID verification. No partial group/ref was accepted. All seven cases passed with the small IPLD corpus and again with a 1 MiB incompressible block in the first archive.

The test uses hosted Babashka and already generated pinned Forest archives. The small-fixture proof is added to the Nix check; the pinned Linux Forest job additionally generates and tests the 1 MiB archive. Local Nix evaluation is unavailable, so exact-head CI remains required. This supplements the earlier record `README-generic-atomic-group-ref-20261115.md`, which predates the process-kill proof. It is process death with OS cache retained, not guest restart, host-cache loss, actual power failure, Native, witness or distributed fencing. The API is not yet wired into the streamed Kotobase builder.
