# Same-store nonce, group and ref publication — 2026-11-15

The hosted product streamed API accepts an optional nonce reference and marker CID. Under the existing local writer lock, it requires that nonce ref to be absent, checks that the marker CID is in the staged Forest group, and publishes group, target ref and nonce ref in the same `:put-many` WAL frame. The caller-supplied closure verifier must authenticate the canonical marker and its scope; staging a block is not sufficient authority. This primitive does not reserve a nonce before query evaluation.

On macOS arm64, Babashka 1.12.218 and pinned Forest v0.39.0 wrote and separately reopened 19 blocks across at least two Packs. Missing marker and rejected closure left the original root unchanged; reuse of the nonce was refused and left the published root unchanged. Three synchronized two-writer trials yielded exactly one published ref and one refused writer, with the nonce ref in the winner's only WAL frame. The existing no-nonce two-Pack write/read proof also passed. These cover a cooperative local store, not distributed fencing or crash durability.

A separate hosted JVM oracle used the actual Kotoba bounded codec to create the `:kotobase.nonce/key-v1` and `:kotobase.nonce/consumed-v1` values, wrote the marker with a separate target in one group/frame, then opened the store in a fresh JVM with the writer unavailable. With Kotobase nonce-store change [PR #101](https://github.com/cloud-itonami/app-itonami-kotobase/pull/101) commit `6833830`, replay returned false and the store root was unchanged. The old nonce consumer attempted an unnecessary writer operation and failed before refusal. Fixture identity/scope are not production authority. The oracle is not a Native build, CI gate or fallback.

The oracle and test sources are in this directory and `test/otehon`; outputs and staging are retained in task scratch. No downloads were made.

This is one local root and a caller-verified marker, not an atomic authority/nonce/receipt transaction across independent stores. Host key custody, pre-evaluation nonce admission, rollback resistance, concurrent GC, independent nodes, physical power-loss and Native execution remain open. The two hosted CI proofs are wired into the Otehon Linux job; exact-head CI is separate evidence.
