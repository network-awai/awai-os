## 表示問題の現在地

**訂正（2026-11-17 06:48 UTC 追記）**: 当初の記述は接続端子を逆に読んでいた。kernel は `HDMI-A-2` と `DP-1` の2出力を connected と報告し、drm_hwcomposer は `HDMI-A-2` を display #0（Primary）、`DP-1` を display #1 に割り当てていた。Android の display0 が物理 HDMI、display2（Android の汎用ラベル「HDMI画面」）が DP-1 である。`physical-hdmi.png` はカメラやキャプチャ機器ではなく display2 の `screencap` だった。display0 には LineageOS SetupWizard の WelcomeActivity が表示され、`user_setup_complete=0` と `device_provisioned=0` は初期設定が未完了という正しい状態を示す。display2 への Activity 起動で観測した `Skipping, user setup not complete` も同じ理由による。

所有者は DP-1 モニターを desktop として選択した。実行時に `vendor.hwc.drm.primary_display=DP-1` を設定して hwcomposer と framework を再起動すると、DP-1 が display #0 になり、SetupWizard が DP-1 に表示された（`dp1-primary.png`、HDMI-A-2 は未接続扱い）。この設定は再起動で消えるうえ、vendor/system image は読取り専用で、`androidboot` パラメータからも設定できない。永続化には、iPXE の kernel 引数へ `video=HDMI-A-2:d` を加える `android/desktop/netboot/select-primary-display.mjs` を使う。これは固定した persistent-v6 の `ipxe.efi` だけを入力として受け付け、PE 配置を保ったまま埋め込みスクリプト領域だけを書き換える。配信経路の切替と再起動による確認は、所有者が初期設定を終えた後に行う。provisioning フラグは直書きしない。

ユーザー提供写真の systemd emergency/root locked は旧 OS への fallback と整合する。ACPI の警告だけで停止原因とは断定しない。UEFI 読取りでは HTTP/PXE が旧 Awai Otehon より先。BootOrder は変更していない。BootNext の書込み試行はタイムアウトし読戻し未確認のため、成功した設定として扱わない。今回の無操作再起動成功は実際の HTTP GET と異なる boot ID で判断する。

## ここからの工程

1. **AWAI-3049**: AOSP Setup/Home と主・外部画面 policy を調査し、所有者が選んだ DP-1 モニター上で setup と Home を表示する。Figma 正本の構成を保つ。provisioning フラグの直書きで回避しない。
2. VM で正規 setup lifecycle、画面切替と再起動を確認し、実機 DP-1 モニターの物理画面・入力・Home の復元を確認する。display0 の CDP だけを表示受入に使わない。
3. QA ランナーの起動直後 retry を含め再実行し、失敗・続行・完走を別記する。本人登録は必要な実受入に限定する。
4. PR169 のレビュー・exact-head CI。Actions 全体を有効にすると既存の別 workflow も動くため、QAのCI定義追加とリポジトリ全体の運用変更を混同しない。
5. 認証・Android images・起動サービスを保持。旧 Nix store は暗号化保存済みの隔離状態で、この工程では削除していない。p2 は Android images を共有するので format/delete しない。

起動参照用に復旧した旧パスは **互換 symlink であり Git checkout ではない**。実体は現在の QA task output と persistent-data 作業領域にある。稼働依存がある間は、merged 判定だけでこの task output・起動 artifact・サービスを削除しない。長期の固定配信場所への移行は、切替と読戻しを別途検証する。

見積単位・モデル設定・issue別 token/cost・active/wait は unknown。レポートの開始・終了時刻は wall time の証拠で、専有実行時間や完成率ではない。
