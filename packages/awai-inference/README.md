# Awai device-local inference handoff v1

`client.js` exports `createInferenceClient({invoke})` with `info()`, `open()` and `generate({prompt,modality:'text'|'image',maxTokens})`. It performs no fetch, model download, approval persistence or remote fallback. Native Tauri hosts expose **only** `awai_local_inference` through the Android `InferenceClientPlugin`; see the concrete integration in `apps/itonami`.

Android consumers need the `network.awai.permission.LOCAL_INFERENCE` uses-permission, package visibility for `network.awai.murakumo`, the shared Android source directory and a scoped Tauri command/capability. The provider checks caller package **and** signature, and each generation opens its native confirmation. Explicit Activity results bind schema/requestId/engine/modality and byte bounds. A native permission alone does not auto-approve a request. Readiness uses the signature-protected read-only provider; it never infers a model is loaded from app installation.

The currently admitted app IDs include Itonami, Gaka/Mangaka, Dougaka/Animeka/Ongakuka and Rodo (`network.itonami.rodo`, the labor-family Itonami bot app, AWAI-3180). This is eligibility, **not evidence that all those apps are packaged, integrated or accepted**. This engine currently implements text. Creative apps can use it for text/prompt assistance; image/video/audio synthesis must refuse or use a separately implemented, explicitly selected actual backend. No returned text may be relabeled as generated media.

For the isolated Nix shell build closure, `otehon/shell/vendor/awai-inference-client.js` is an exact copy with a SHA256 pin, regenerated into its source tree by `sync-vendor.mjs`. The canonical Kotoba consent broker remains independently pinned and unchanged. This adapter does not validate external descriptors, grant operations or replace the broker. Keep SDK and vendor bytes equal when changing the source.

Text generation is local host computation. External model/runtime acquisition, profile transfer, remote inference, app iframe transport and Awai FS sync retain their own canonical declarations/consent/verification. These are not supplied by this package. The current app has a native SAF import for the exact pinned model and no network permission.

Image requests use the fixed Qwen Image2.1 Turbo AD-Q2_K set (image-pins.json),512×512,Vulkan0,8 Euler steps,CFG1 and the publisher sigma schedule. No CPU or remote image fallback. Native Murakumo validates all three model bytes/SHA before generation and releases the image context after each job. The signed Activity result carries a read-granted provider URI; the client checks exact provider authority, request/model ID, bounded PNG dimensions/bytes and SHA before copying to its own files. WebView receives a bounded data URL, not an arbitrary path or remote URL.

`saveImage(imageId)` accepts only the generated request ID already in client storage, asks native operation-specific confirmation, adds a new PNG to MediaStore Pictures/Awai without replacing an existing item, and reads it back before resolving. No owner login or owner key is required for isolated QA. This local image save is not distributed AwaiFS durability. Model provisioning and persistent storage are separate: the current physical qualification may explicitly use a temporary RAM model directory due to limited userdata capacity.
