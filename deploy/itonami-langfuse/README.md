# Private Itonami Agent Langfuse

This operator deployment receives the Otehon Agent's metadata-only OTLP spans. It is scoped to the Agent owner's host. It uses dedicated persistent Docker volumes in a dedicated VM, without mounting the macOS home directory or publishing via Funnel. The UI and OTLP endpoint use the same loopback listener. A multi-host deployment needs its own HTTPS transport and access policy.

1. Verify the [upstream v4.82.0 Compose file](https://github.com/langfuse/langfuse/blob/v4.82.0/docker-compose.yml) against SHA-256 `c70d77f1b450435bc9539a8824555c0c90d31037b53a28cbd26205b3ccff0652`. Use the private overlay and Compose 2.40.3 or newer. Resolve and record image digests before deploying.
2. Provision independent secrets in a mode-0600 environment file inside the guest. Set `LANGFUSE_IMAGE_TAG=4.82.0`, `NEXTAUTH_URL=http://127.0.0.1:32111`, and `TELEMETRY_ENABLED=false`. Set `NEXTAUTH_SECRET`, `SALT`, a 32-byte hex `ENCRYPTION_KEY`, PostgreSQL password and matching `DATABASE_URL`, ClickHouse password, Redis password, and matching MinIO/S3 event, media and export credentials. Use `LANGFUSE_INIT_*` to seed an owner and a dedicated production project on the first startup. Do not store credentials in the repo or issue.
3. Start `langfuse-web` and `langfuse-worker` with their dependencies. Use `docker compose ... config --format json` to check that only the Langfuse web listener is published and only on IPv4 loopback. Check `/api/public/health`, credentialed owner sign-in and the project's observation API. For installation on a separate operator machine, forward loopback via approved SSH and preserve the configured local URL.
4. Set the Agent's `telemetry.endpoint` to `http://127.0.0.1:32111/api/public/otel/v1/traces` and `telemetry.authorizationFile` to an owner-only file with the project's Basic header. Apply the [`bot-chat` runbook](../../otehon/bot-chat/README.md) for the outbox, origin, and service configuration. Verify readback using one fresh production turn and the same trace/session IDs in both views. Preserve the previous Agent configuration and launch definition for rollback.

This profile is single-host. VM/host failure can interrupt ingestion and the UI. Use the Agent outbox for short interruptions, and keep backups separately from the running VM and verify restores before depending on long-term history. Vendor guidance covers [multi-host production hardening](https://langfuse.com/resources/engineering/self-hosted-langfuse-production-checklist) and [backup procedures](https://langfuse.com/self-hosting/configuration/backups).
