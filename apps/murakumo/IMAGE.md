# Android local image generation

AWAI-2927 connects the fixed Qwen Image2.1 Turbo Uncensored AD-Q2_K text encoder, matching Turbo AD-Q2_K denoiser and BF16 VAE to a separately pinned stable-diffusion.cpp Android Vulkan library. This is an explicitly selected quantization of the existing model family, not a substitute image model. See image-pins.json for exact revisions, byte lengths and SHA256. The host build script verifies upstream source archives and extracted files; it does not run a host model or mutate a device. Build image-native separately from the text library because they pin different ggml versions; static hidden linking prevents symbol interposition.

Generation: fixed512×512, seed42,8 Euler steps,CFG1,publisher sigma schedule;Vulkan0 compute,CPU parameter storage. No remote or alternate CPU image-engine fallback. There is one shared text/image job slot. A loaded text model must be released before an image request. The image context is released after each request; native cancellation is cooperative and is not an authentication bypass.

Itonami's Murakumo panel selects text/image, uses the signature-protected native per-request confirmation, displays a bounded verified PNG and saves it through a separate native confirmation. Murakumo checks all model file sizes and hashes before inference. The client verifies request ID, fixed model ID, source provider authority, PNG bounds and digest before retaining the output. MediaStore save creates a new item, reads back its bytes/SHA and only then publishes it. No arbitrary path/URL, overwrite, storage-wide permission, prompt logging or image upload.

The actual PC has about24GB RAM but its Android userdata is about6GB with less than3GB free. The6,565,132,376-byte model set therefore cannot be retained in userdata. For this physical acceptance unit, the operator stages public, hash-verified weights in a separately named temporary RAM directory and points only the owned app's image-model directory there. Original model artifacts remain on the host. This is explicit temporary model provisioning: an APK update does not enlarge storage, and reboot-persistent model availability remains a separate gate. Generated image save uses normal userdata/MediaStore and is verified independently. No partition, encrypted volume, owner profile, cache setting, system service or boot image is changed by this implementation.
