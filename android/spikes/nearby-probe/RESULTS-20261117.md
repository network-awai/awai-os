## 権限

- API 37 には `android.permission.ACCESS_LOCAL_NETWORK` がある。
- 実行時の確認ダイアログは両端末とも **1 回だけ**：「付近のデバイスの検出、接続、相対位置の特定を … に許可しますか？」。
- これを許可すると `ACCESS_LOCAL_NETWORK`、`NEARBY_WIFI_DEVICES`、`BLUETOOTH_SCAN`、`BLUETOOTH_ADVERTISE`、`BLUETOOTH_CONNECT` の 5 つがまとめて許可された（付近のデバイスのグループ）。
- **`ACCESS_LOCAL_NETWORK` は強制される。** Wi-Fi（moto）と Ethernet（6600H、`pm revoke` で 1 つだけ取り消し）の両方で確認した。
  - **告知:** `NsdManager.registerService` が `SecurityException: Missing local network permission` で失敗する。
  - **検索:** 例外は出ず `onDiscoveryStarted` まで進むが、Mac が告知していても結果は 1 件も届かない。黙って何も見つからないので、実装では開始前に権限を確認し、未許可を利用者に表示する必要がある。
- 権限なしの Wi-Fi Direct は `reason=0`（ERROR）で失敗し、許可後は成功した。
- 権限なしの BLE 告知は、最初の版ではデータ長の超過（下記）で先に失敗したため、権限の影響は切り分けていない。

## マルチキャストロック

moto の NSD 検索は、`WifiManager.MulticastLock` があってもなくても同じ結果（検出・解決とも成功）だった。NSD はシステムのサービスが受信するので、アプリ側のロックは不要と判断する。

## BLE の注意点

- **データ長の上限:** 従来の BLE 告知は 31 バイトまで。128 ビット UUID の一覧と 128 ビット UUID の service data を両方入れると超過し、`onStartFailure(1)`（DATA_TOO_LARGE）になった。
  - service data だけ（flags 3 + 2 + 16 + 9 = 30 バイト）にして成功した。
  - 検索側は `ScanFilter.setServiceData`（先頭 1 バイトをバージョンとして一致）で絞り込んだ。
  - 設計の「service UUID を告知し、service data に v とトークン」は、この形に修正する。
- **6600H に `bluetooth_le` 機能が無い理由:**
  - コントローラは Realtek の USB（`0bda:b850`、ドライバ `btusb`）で、LE に対応している。アダプタも `leScanner`、`leAdvertiser`、`multiAdv`、`extAdv` をすべて true と報告した。
  - Generic イメージは `/vendor/etc/permissions/android.hardware.bluetooth.prebuilt.xml`（`android.hardware.bluetooth` だけ）を入れており、`android.hardware.bluetooth_le.xml` を入れていない。
  - つまりイメージ設定の欠落で、ハードウェアや BLE スタックの問題ではない。同様に `android.hardware.ethernet` も報告されないが、`eth0` で動作している。
  - 製品 AOSP の機種設定では `bluetooth_le` と `ethernet` の機能ファイルを入れること。`uses-feature` で絞る配布や、機能フラグで分岐するコードが誤判定するため。

## プライバシー上の発見

- **NSD が固定のホスト名を告知する:** Android の NSD は、サービス名とは別に `Android_GZL30H1S.local`（moto）、`Android_WEMP1A7X.local`（6600H）というホスト名を告知した。サービス名を「Awai」、TXT をランダムな `t` にしても、このホスト名で端末を見分けられる可能性がある。
  - 再起動や時間でホスト名が変わるかは未確認。
  - 設計の「固定 ID を流さない」を満たすかは、この確認が要る。
- **BLE はアドレスを公開しなかった:** 端末名を含めず（`setIncludeDeviceName(false)`）、受信側のログにも service data の有無と RSSI しか出していない。

## 再現手順

```bash
python3 android/spikes/nearby-probe/build.py
adb -s SERIAL install -t -r --no-incremental .agent-output/nearby-probe/nearby-probe.apk
adb -s SERIAL shell am start -n network.awai.nearbyprobe/.ProbeActivity --es op perms
adb -s SERIAL shell am start -n network.awai.nearbyprobe/.ProbeActivity --es op nsd-adv
adb -s SERIAL logcat -s AwaiProbe:I
adb -s SERIAL uninstall network.awai.nearbyprobe
```

op には `state`、`perms`、`nsd-adv`、`nsd-browse`、`ble-adv`、`ble-scan`、`p2p`、`stop` がある。Mac 側では `dns-sd -B _awai-pair._tcp local.`、`dns-sd -L Awai _awai-pair._tcp local.`、`dns-sd -R Awai-mac _awai-pair._tcp local. 4242 v=1 t=test` を使った（`dns-sd` は終了しないので `timeout` を付ける）。
