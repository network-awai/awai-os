## 2. Module packaging + load order (device/virt/virtio-common, pinned SHA)

Packaging: no new Soong/Makefile needed — `BoardConfigCommon.mk:40-43`
(after patch, lines shifted) already stages kernel modules into the vendor
image (`BOARD_VENDOR_KERNEL_MODULES := $(wildcard $(TARGET_PREBUILT_KERNEL_DIR)/*.ko)`
for prebuilt; source builds stage via `vendor/lineage:build/tasks/kernel.mk`
`KERNEL_MODULES_PARTITION_FILE_LIST`). The four modules are exactly the ones
the Kconfig selects (`rtw89/Kconfig` + `rtw89/Makefile`: `rtw89_core.o`
`rtw89_core-y` list, `rtw89_pci.o`, `rtw89_8851b.o`, `rtw89_8851be.o`).

`BOARD_VENDOR_KERNEL_MODULES_LOAD` (added after the e1000e/igc block,
following its AWAI-3586 precedent). Order, core first:

```sh
rtw89_core.ko -> rtw89_8851b.ko -> rtw89_pci.ko -> rtw89_8851be.ko
```

Full boot order: `rfkill → cfg80211 → mac80211 → rtw89_core → rtw89_8851b →
rtw89_pci → rtw89_8851be`. `cfg80211.ko`/`mac80211.ko` are not relisted
(they predate this change and are already shipped from `gki_defconfig =m`).
`rtw8851be.c:81-88` declares `MODULE_DEVICE_TABLE(pci, rtw89_8851be_id_table)`
for Realtek PCI `0xb851` (`module_pci_driver(rtw89_8851be_driver)`), so PCI
autoload would also load `rtw89_8851be.ko` on device match; the explicit
LOAD entry pins boot-time order.

**未確認**: whether `init` honours `BOARD_VENDOR_KERNEL_MODULES_LOAD` order
strictly on this product (not built/booted here), and prebuilt-kernel
(`TARGET_PREBUILT_KERNEL_DIR`) module file names beyond the Makefile objects.
