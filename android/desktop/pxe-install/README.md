# PXE persistent install for the 7735HS (AWAI-3585/AWAI-3586)

A decision-ready disk plan plus a PXE installer profile that delivers a
persistent Awai OS PC installation over the direct LAN without touching any
existing boot entries. All destructive steps stay the owner's hand.

The 7735HS NVMe (512-byte sectors, 500118192 sectors) currently holds:
p1 otehon-esp 2048-2099199, p2 otehon-root ext4 2099200-52430847 (24 GiB,
hosts `/awai-android-2992`), p3 otehon-state LUKS 52430848-500118158
(~213 GiB). Free range: only 34-2047 (2014 sectors, nothing aligned), and
`awai-pc-install.py plan` refuses: need 60082176 sectors (28.65 GiB, 16 GiB
userdata) in one aligned range. See [evidence/disk-plan-20261123.json](evidence/disk-plan-20261123.json),
generated by `generate-disk-plan.py` from the recorded GPT, exercising the
real `make_plan()` with `table()` mocked the way `test_awai_pc_install.py`
does (sgdisk is not on the operator Mac).

## Disk options (sector-exact) — candidate order

> **2026-11-24 owner decision: (c) second disk. (a) erase and (b1) p3-tail
> truncate are NOT approved and are out of scope for execution** (they
> destroy existing data). (a)/(b1) below remain documented as history.

1. **(c) Second disk** — decided. The current NVMe stays untouched.
2. **(a) Erase `nvme0n1`** — NOT approved (historical option only). Fastest,
   but all existing data is lost.
3. **(b1) Shrink only p3's tail** — NOT approved (historical option only).
   The LUKS volume's last 28.65 GiB of data is lost. The LUKS header,
   p1 and p2 remain — that is **data loss, not a data-retention
   shrink**: truncating a LUKS container does not preserve its tail.

**(c) required spec:** 512e (512-byte logical sectors), ≥ 64 GiB. Confirm
with `sgdisk -p <disk>` that the logical sector size is 512 bytes before
running `awai-pc-install.py plan`. A 4Kn disk stops there — the installer
refuses non-512 logical sectors and never reaches `plan`.

| Option | What happens | Destroys | Plan |
| --- | --- | --- | --- |
| (c) Second disk | blank-disk free [2048, 500118158...] (any 512e disk ≥ 60084257 sectors; recommend ≥ 64 GiB) | only the new disk; the current NVMe is untouched, safest | ok, 11 partitions |
| (a) Erase `nvme0n1`, install A/B fresh | free [2048, 500118158] = 500116111 sectors ≥ 60082176 | p1 ESP, p2 (root + `/awai-android-2992` persistence images), p3 LUKS — total loss; needs encrypted backup of p2 contents and p3 first | ok, 11 partitions (plan in evidence JSON) |
| (b1) Shrink only p3's tail | p3 end → 440035327, new free [440035328, 500118158] = 60082831 sectors ≥ need | **LUKS volume's last 28.65 GiB of data is lost** (LUKS header, p1, p2 remain — not data retention) | ok (11 partitions) |
| (b2) Shrink p2 alone | max frees 50331648 < 60082176 | even *deleting* p2 cannot fit this layout | impossible — installer needs a single range bigger than all of p2 |
| (b3) Free a gap before p3 | requires moving p3's start (LUKS header lives at p3 start) | destroys the LUKS header ⇒ identical to losing all of p3 | not viable |

The KVM 2026-11-19 source sizes total *exactly* 60082176 aligned sectors,
matching the pinned cd22c762 candidate total, so the cd22c per-partition
split is almost certainly identical — but only its total is pinned; the

## PXE install profile

New, additive profile beside the five existing entries. Nothing existing
is replaced; the firmware route (`activate-route.mjs`/`switch-route.mjs`)
decides which artifact directory is live, and the operator switches it back
afterward.

- `../persistence/patch-ipxe.mjs <in> install <out> [erase|shared|second] [sectors]`
  — same port/blacklist ops as the other modes; appends only a short
  `awai.install.profile/mode/sectors` marker. Image sha/bytes/url pins live
  inside the initrd overlay (`/awai/install.pins`, template
  `../persistence/install.pins.template`), digest-covered by the serve
  manifest's whole-initrd pin — never long cmdline text the embedded
  region cannot grow to hold (the script refuses loudly if it can't fit).
- `../persistence/serve-install.mjs <dir> <manifest.json>` — same static,
  manifest-pinned server as `serve-artifacts.mjs`, plus `install.img`,
  on the same 10.77.0.1:18091.
- `../persistence/init-install.sh` — BusyBox init with fixed profile `1`.
  The boot arguments must agree with the initrd pins. The historical
  `erase` profile requires exactly one NVMe namespace with 500118192
  sectors and the pinned root/LUKS UUIDs. Both modes check the NIC MAC
  against an allowlist file before configuring the link or starting
  diagnostics (see "NIC allowlist" below) — there is no MAC pinned in the
  script itself. `shared` always reports `shared-not-implemented`.
- The installer downloads the image once over direct-LAN HTTP to a
  size-limited tmpfs. It checks the exact length, remounts the copy
  read-only, and checks its SHA-256 against the initrd pin. Insufficient RAM
  stops installation before download. The operator must type the complete
  digest on the console. The installer writes the verified copy with a
  sector count taken from the aligned image size, syncs, and prints
  `AWAI_INSTALL_COMPLETE` only after the readback digest matches.
- `REFUSED … (disk untouched)` indicates a failure before the write starts.
  `PARTIALLY WRITTEN … (disk contents unverified)` indicates a failure
  once writing has started, including a failed sync or readback. Treat
  the disk as modified and use the owner's recovery procedure before
  attempting to boot from it.

### NIC allowlist (installer MAC guard)

`init-install.sh` used to hard-pin one NIC MAC, so every other machine was
refused a persistent install even when it was the intended target. The pin
is gone: the script reads an allowlist and fails closed.

- **Default path:** `/etc/awai/installer-macs.txt` inside the install
  initrd overlay (next to `/awai/install.pins`). One MAC per line; blank
  lines and lines whose first non-space character is `#` are ignored.
  Upper/lower case and `:` vs `-` separators are normalized before
  comparison; the sysfs address is normalized the same way.
- **Fail closed:** with no allowlist file, with no entries (empty or
  comment-only), or with any malformed entry, the installer prints
  `REFUSED missing-installer-macs` / `empty-installer-macs` /
  `malformed-installer-macs` and stops before configuring the link or
  starting diagnostics. The disk is untouched.
- **Bundled default:** `../persistence/installer-macs.txt` ships with the
  one existing machine (`0c:47:a9:60:9d:34`) already listed, so that
  machine keeps working unchanged. A second PXE-confirmed machine (Ryzen 5 6600H, measured
  2026-11-24; not the 7735HS, disk not audited) is recorded there as a
  commented, disabled example only. Copy the file into the overlay at
  `/etc/awai/installer-macs.txt` when assembling the initrd, the same way
  `install.pins.template` goes to `/awai/install.pins`.
- **Adding a machine:** append one line with its NIC MAC to the copy in
  the overlay, rebuild the initrd, and re-pin the manifest digests (no
  kernel or image rebuild, and no change to the install script). The next
  PXE boot then accepts that machine.
- **Overriding the path** (priority order): kernel argument
  `awai.install.macs=<absolute-path>` over environment variable
  `AWAI_INSTALLER_MACS=<absolute-path>` over the default
  `/etc/awai/installer-macs.txt`. The path must be absolute; a duplicate
  `awai.install.macs=` argument or a relative path refuses with
  `invalid-installer-macs-path`.

### Second-disk mode

Option (c), the owner's approved install path, writes only to the blank second
disk. Keep the original 7735HS NVMe connected. Init verifies its pinned root
and state UUIDs and requires a different device and serial for the target.

Use a second disk with 512-byte logical sectors (512e), at least 64 GiB per the
device specification, and enough capacity for the complete image. Fill in
`install_mode=second`, `target_serial` from the target's sysfs `device/serial`,
and `target_sectors` from its sysfs `size` in the digest-pinned initrd
`install.pins`. Place `init-install.sh` in the overlay as the executable
`/awai-netboot` selected by the retained `rdinit` boot argument. Patch iPXE
with `install <out> second <target_sectors>`.
The init scans the entire target for zero bytes before bringing up the LAN.
If it finds any data, deliberately blank the second disk before retrying.
